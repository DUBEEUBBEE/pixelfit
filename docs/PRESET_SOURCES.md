# 픽셀핏 규격·프리셋 출처 기록

문서 기준일: 2026-07-23 (Asia/Seoul)

이 문서는 도구 Registry와 가이드가 사용하는 수치의 출처, 제품 해석과 자동 검사의 한계를 기록한다. `official`은 기관 페이지에서 확인한 값이고, `convention`은 특정 기관의 보편 의무 규격이 아닌 픽셀핏 서비스 기본값 또는 일반적 제작 관행이다.

`lastVerifiedAt`은 해당 날짜에 링크와 문구를 확인했다는 의미다. 이후 변경이 없거나 실제 접수·노출·승인이 보장된다는 뜻이 아니다. 공식값을 바꿀 때는 문서, Registry, UI, 계산과 테스트를 같은 변경으로 갱신한다.

## 2. 한국 온라인 여권사진

- 기관: 대한민국 외교부 여권과
- 출처 1: [온라인용 사진파일 안내](https://www.passport.go.kr/home/kor/contents.do?menuPos=12)
- 출처 2: [온라인 여권 사진 검증](https://www.passport.go.kr/home/kor/onlinePhotoVerify/index.do?menuPos=33)
- Registry 확인일: 2026-07-22

확인한 값과 제한:

- 온라인용 안내는 JPG/JPEG, 500KB 이하, 권장 413×531px을 제시한다.
- 업로드 허용 범위는 가로 395~431px, 세로 507~550px이며 300dpi를 권장한다.
- 3.5×4.5cm 인화 기준에서 정수리부터 턱까지 머리 길이는 3.2~3.6cm다.
- 배경 제거·흰 배경 합성, 얼굴 비율 변형 등 변형 사진을 제출 불가 사례로 설명한다.
- 검증 페이지의 판정은 참고용이며 실제 심사를 보장하지 않는다.

제품 해석:

- 혼란을 줄이기 위해 기본 출력은 413×531px JPEG 하나다.
- 500KB는 인코드 후 실제 `Blob.size <= 512000`으로 검사한다.
- 531px에서 머리 길이 환산 약 378~425px은 안내선/휴리스틱이며 자동 승인 판정이 아니다.
- 배경 제거·교체, retouch, 생성형 수정은 Registry와 실행 게이트에서 금지한다.
- 촬영일, 표정, 가림, 렌즈, 피부색, 최종 심사는 자동 확정하지 않는다.

## 3. 주민등록증 사진과 일반 증명사진

### 주민등록증

- 기관: 대한민국 행정안전부
- 출처: [모바일 신분증 — 모바일 주민등록증 발급 안내](https://www.mobileid.go.kr/mip/hps/issuReqstGuidance/issuReqstGuidanceMrc.do)
- 추가 확인 대상: [정부24 주민등록증 재발급 신청](https://www.gov.kr/mw/AA020InfoCappView.do?CappBizCD=13100000018)
- Registry 확인일: 2026-07-22

확인한 공식값은 “6개월 이내 촬영된 사진 1장(3.5×4.5cm)”의 물리 크기다. 확인 당시 정부24 상세 URL에서는 별도 온라인 픽셀·형식·용량 값을 확정하지 못했다.

따라서 `round(cm / 2.54 × 300)`으로 계산한 413×531px은 픽셀핏의 300dpi 서비스 기본값이다. 모든 주민등록증 온라인 제출 경로의 공식 픽셀값으로 표시하지 않는다. 현재 제출 화면이 다른 값을 직접 요구하면 그 값이 우선한다.

### 일반 증명사진

- 기관/단일 공식 URL: 없음
- 구분: `convention`
- 채택일: 2026-07-22

3×4cm를 300dpi로 환산한 354×472px을 서비스 기본값으로 사용한다. 국내에서 널리 쓰이는 인화 관행이지 모든 기관의 법정·공식 온라인 규격은 아니다. 제출기관이 요구하는 물리 크기, 픽셀, 배경색, 형식과 용량을 마지막에 확인해야 한다.

## 4. YouTube 채널 배너

- 기관: Google LLC / YouTube
- 출처: [YouTube 고객센터 — 채널 브랜딩 관리](https://support.google.com/youtube/answer/10456525?hl=ko)
- Registry 확인일: 2026-07-22

확인한 공식값:

- 최소 업로드: 2048×1152px, 16:9
- 최소 크기 기준 텍스트·로고 안전영역: 1235×338px
- 권장 업로드: 2560×1440px
- 파일 크기: 6MB 이하
- 기기에 따라 배너 표시 영역이 달라지고 잘릴 수 있음

픽셀핏은 권장 2560×1440으로 출력한다. 안전영역은 최소 캔버스 기준을 1.25배 해 약 1544×423px로 표시한다. TV·desktop·mobile overlay는 안전영역 이해를 돕는 예상치이며 실제 YouTube UI를 보장하지 않는다.

## 5. YouTube 썸네일

- 기관: Google LLC / YouTube
- 출처: [YouTube 고객센터 — Add video thumbnails on YouTube](https://support.google.com/youtube/answer/72431?hl=en)
- Registry 확인일: 2026-07-23

확인한 현재 공식값:

- 권장 해상도: 3840×2160px
- 최소 너비: 640px
- 권장 비율: 16:9
- 지원 안내 형식: JPG, GIF, PNG
- 동영상 custom thumbnail 파일 한도: 모바일 업로드 2MB, desktop 업로드 50MB

픽셀핏의 기본 출력은 3840×2160 JPEG/PNG다. 모바일과 desktop의 공식 한도가 다르므로 현재 도구는 하나의 공통 용량 통과를 약속하지 않고 실제 결과 byte를 보여 준다. 텍스트 템플릿, 모바일 축소 미리보기와 여백은 제품 UX이며 YouTube의 공식 안전영역이나 노출/CTR 보장이 아니다. 과거에 흔히 사용하던 1280×720을 최신 권장값처럼 표시하지 않는다.

## 6. 파비콘 패키지

- 기관: Google Search Central
- 출처: [Google 검색결과에 표시할 파비콘 정의하기](https://developers.google.com/search/docs/appearance/favicon-in-search?hl=ko)
- Registry 확인일: 2026-07-22

검색 파비콘에서 확인한 기준은 1:1 정사각형, 최소 8×8px, 더 나은 표시를 위한 48×48px 초과 권장, 크롤링 가능한 안정 URL이다. 이 기준을 지켜도 Google 검색결과 표시가 보장되지 않는다.

픽셀핏의 16/32/48px PNG와 다중 크기 ICO, 180px Apple touch icon, 192/512px 앱 아이콘, `site.webmanifest`, README와 설치 안내 ZIP은 브라우저·PWA 호환 편의를 위한 제품 결정이다. 전체 패키지가 Google의 공식 의무 목록이라는 뜻은 아니다. 래스터 입력을 SVG나 벡터로 바꿨다고 주장하지 않는다.

## 7. 사진 개인정보 정리

- 기관/단일 공식 규격: 없음
- 구분: `convention`과 제품 개인정보 정책
- 채택일: 2026-07-22

JPEG, PNG, WebP container에서 알려진 개인정보성 EXIF/XMP/IPTC를 선택적으로 제거하고 결과를 다시 파싱한다. 지원 경로에서는 JPEG scan, PNG IDAT, WebP image payload 보존을 우선하지만 실제 확인된 속성만 보존되었다고 표시한다.

C2PA, JUMBF, Content Credentials 등 출처 정보는 제거 선택지로 제공하지 않는다. 파일 구조 변경만으로 자격 증명 유효성이 영향을 받을 수 있으므로 “완전 보존”도 보장하지 않는다. 모든 제조사 고유 metadata를 찾거나 완전한 익명화를 보장하지 않는다.

## 8. v2 서비스 도구

다음 값은 특정 플랫폼의 공식 의무 규격이 아니라 현재 구현의 제품 계약이다.

### 사진 용량 줄이기

- 100KB, 200KB, 500KB, 1MB, 2MB preset과 직접 입력을 제공한다.
- 목표는 상한이며 실제 Blob 바이트로 성공 여부를 판정한다.
- 품질 탐색은 횟수를 제한하고, 사용자가 허용한 경우에만 해상도를 최대 4단계 축소한다.
- 현재 한 장씩 처리한다. 목표 미달을 숨기지 않는다.

### 이미지 크기 조절

- 직접 가로·세로, 긴 변, 퍼센트 모드를 제공한다.
- 비율 잠금이 기본이며 contain/cover를 명확히 구분한다.
- 업스케일은 없는 디테일을 복원하지 않으므로 경고한다.

### 이미지 형식 변환

- JPEG, PNG, WebP만 입력·출력 범위로 한다.
- JPEG는 투명을 지원하지 않아 선택 배경으로 합성한다.
- 형식 변환은 재인코딩 경로이며 원본 EXIF·ICC·metadata 보존을 약속하지 않는다.
- HEIC은 검증된 로컬 디코더가 없어 지원하지 않는다.

### SNS 이미지 세트

- 1:1 1080×1080, 4:5 1080×1350, 9:16 1080×1920을 서비스 preset으로 제공한다.
- 각 비율의 crop을 별도로 저장하고 개별 파일 또는 ZIP으로 다운로드한다.
- 원형 프로필과 상하 UI 가이드는 예상 미리보기이며 플랫폼 실제 표시를 보장하지 않는다.

### 네컷사진

- 세로 1200×1800, 가로 1800×1200은 디지털 공유용 서비스값이다.
- 사진 1~4장을 사용하며 부족하면 선택한 사진을 순환 반복한다.
- 프레임·필터·날짜·짧은 문구·순서·crop을 제공한다. 특정 인화업체 규격이나 상표 제품을 모사한다고 주장하지 않는다.

### 필름사진

- grain, vignette, light leak, 날짜, 흑백, 저채도, flash와 강도는 로컬 결정적 픽셀 연산이다.
- 같은 입력·설정·seed에서 재현 가능한 결과를 목표로 한다.
- 생성형 AI나 실제 필름/렌즈/현상 공정의 인증된 재현이 아니다.

## 10. 금지된 주장

- 확인하지 않은 기관 규격을 `official`로 표시하지 않는다.
- 서비스 환산 픽셀을 보편적 온라인 규격으로 확대하지 않는다.
- 자동 검사로 접수, 승인, 검색 노출, 영상 성과를 보장하지 않는다.
- 존재하지 않는 review, rating, 사용량, 작성자, 촬영일, `dateModified` 또는 metadata를 만들지 않는다.
- HEIC, SVG 벡터화, metadata 완전 보존, Content Credentials 유지가 구현·검증되지 않았는데 성공으로 표시하지 않는다.

## 11. 변경 관리

규격이나 출처를 바꿀 때는 다음을 한 변경으로 처리한다.

1. 공식 URL을 직접 열어 현재 문구와 날짜를 확인한다.
2. `src/lib/presets/registry.ts` 또는 `src/config/tools.ts`의 값과 `lastVerifiedAt`을 갱신한다.
3. 관련 가이드, UI 출처·면책, 계산과 테스트를 갱신한다.
4. 빌드·E2E·접근성·공개 URL 검증을 실제 실행한 범위만 기록한다.
5. 실행하지 못한 항목은 `NOT_TESTED`로 남긴다.
