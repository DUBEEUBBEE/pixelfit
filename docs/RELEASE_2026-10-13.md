## 인증 후 이어갈 순서

1. 저장소에 쓸 수 있는 기존 GitHub 인증을 연결한다. 비밀번호·토큰을 문서나 채팅에 붙여넣지 않는다.
2. 로컬 개선 커밋을 별도 브랜치에 전달하고 PR의 GitHub CI 결과를 확인한다. PR을 생성하면 이 작업에 연결한다.
3. 광고 OFF 및 기존 소유권 확인 설정을 보존하여 main에 병합하고 기존 Pages workflow의 성공을 확인한다.
4. 공개 28페이지 정적 감사와 모바일 렌더링, 우선 도구의 실제 다운로드를 검사해 개선본의 공개 반영을 확인한다.
5. AdSense의 해당 사이트에서 실제 반영된 개선 내용을 기준으로 재심사를 요청하고 제출 후 상태를 기록한다. 새 약관 수락·CAPTCHA·추가 본인 인증이 필요한 경우 그 단계는 사용자에게 넘긴다.

새 공개 감사 원본은 `output/release-2026-10-13/public-before-deploy/`에 보존했다. 10월 12일의 테스트·실측·스크린샷을 덮어쓰지 않았다. 승인 여부, 비공개 Google 색인 상태, 실제 사용자 관심도 또는 트래픽을 추정하지 않는다.
