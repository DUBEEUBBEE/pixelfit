# 픽셀핏 v1 제품 명세

기준일: 2026-07-22

## 1. 제품 목표

픽셀핏은 이미지 편집 경험이 거의 없는 사용자가 용도를 고르고 사진을 올리면 출력 픽셀, 비율, 여백, 안전영역, 형식과 용량을 자동으로 맞춰 주는 한국어 웹 애플리케이션이다. 범용 레이어 편집기가 아니라 각 용도에 허용된 작업만 제공하는 제한형 제작 도구다.

대표 문구는 다음과 같다.

- 용도를 고르고 사진만 올리세요.
- 픽셀·비율·용량은 알아서 맞춰드립니다.
- 사진은 이 기기 안에서 처리됩니다.

기본 언어는 한국어이며 문서 루트의 언어는 `ko`다. 브랜드명, 설명, 공개 URL과 연락처처럼 배포별로 달라질 값은 중앙 브랜드 설정에서 관리한다.

## 2. 대상 사용자와 성공 기준

주요 사용자는 모바일을 포함한 일반 사용자, 사진·배너·파비콘 규격을 모르는 사용자, 사진 속 개인정보를 서버 업로드 없이 정리하려는 사용자다.

핵심 작업은 다음 세 단계 안에서 끝나야 한다.

1. 용도를 선택하고 로컬 사진을 고른다.
2. 자동 맞춤 결과를 확인하고 필요할 때 위치, 확대, 회전만 조정한다.
3. 규격과 주의사항을 확인한 뒤 실제 파일을 생성해 다운로드한다.

v1의 제품 성공 조건은 여섯 도구 모두에서 입력부터 다운로드까지 작동하고, 출력 파일을 다시 읽어 크기·형식·용량 등 해당 프리셋이 약속한 속성을 확인하는 것이다. 단순히 화면이 렌더링되거나 빌드되는 것만으로 완료로 보지 않는다.

공통 페이지는 `/`, `/privacy`, `/terms`, `/guide` 또는 `/about`, 그리고 404를 포함한다. 각 도구 페이지에는 고유 제목·설명·canonical·공유 메타데이터·규격 설명·출처·확인일·면책·FAQ·관련 도구 링크를 둔다.

## 4. 범위 밖

회원가입, 로그인, 결제, 클라우드 저장, 관리자 기능, 협업 편집, 사용자별 프로젝트 저장은 만들지 않는다. 얼굴 신원 확인이나 식별, 얼굴·피부·신체 미화, 정장 합성, 공식 사진의 생성형 수정, 범용 텍스트/레이어 편집기도 포함하지 않는다.

SynthID, C2PA, Content Credentials, JUMBF, 디지털 워터마크 또는 다른 출처 표시를 제거·무력화·우회하는 기능과 안내는 금지한다. 작동하지 않는 버튼, 숨겨진 데모, 지원하지 않는 형식에 대한 가짜 성공 상태도 만들지 않는다.

## 5. 제품 정책

### 5.1 공식 사진 무변형 원칙

공식 사진 프리셋은 원본 비율을 유지하는 회전·크롭·위치·확대·리사이즈·형식 변환·제한적 압축·참고용 검사만 허용한다. 여권사진에서는 배경 제거·교체, 흰 배경 합성, 보정, 얼굴 비율 변경, 생성형 확장을 UI뿐 아니라 프리셋 작업 allowlist에서도 차단한다.

### 5.2 승인 보장 금지

자동 검사는 참고용이다. 결과는 `통과`, `주의`, `정보`로 구분하되 실제 접수·승인을 보장하지 않는다. 허용되는 표현은 “규격상 적합 가능성이 높습니다”, “확인이 필요한 항목이 있습니다”, “자동 검사는 참고용이며 실제 심사 결과와 다를 수 있습니다”와 같은 제한된 설명이다.

촬영일, 실제 표정, 렌즈 종류, 미세한 얼굴 가림, 피부색 정확성, 심사관의 판단은 자동 통과 항목으로 표시하지 않는다. 얼굴과 머리 길이 판정은 지원되는 환경에서의 추정치일 뿐이다.

### 5.3 로컬 처리

사용자 파일, 픽셀, Blob, 얼굴 좌표와 메타데이터를 서버에 전송하지 않는다. 이미지 업로드 API와 이미지 영속 저장소를 만들지 않는다. 작업 데이터는 브라우저 메모리에만 두고 초기화·페이지 이탈 때 참조와 Object URL을 해제한다. v1은 이미지 정보가 포함될 수 있는 분석 도구를 기본 사용하지 않는다.

## 6. 도구별 요구사항

### 6.1 한국 온라인 여권사진

- 결과는 기본 413×531px JPEG이며 실제 Blob 크기가 500KB 이하여야 한다.
- 300dpi를 기록한 경우 출력 파일을 다시 파싱해 확인한다.
- 한 명의 얼굴을 찾으면 중앙 맞춤을 제안하고, 0명·여러 명·낮은 신뢰도에서는 경고와 수동 조정을 제공한다.
- 머리 길이 3.2~3.6cm에 대응하는 531px 기준 약 378~425px 범위는 안내선과 휴리스틱으로만 사용한다.
- 출력 픽셀, 파일 크기, 얼굴 수·중심, 흐림·밝기, 가장자리 배경 상태 등 구현 가능한 검사를 제공하되 확정 심사처럼 표현하지 않는다.
- 배경 제거 코드 경로에 도달할 수 없어야 한다.

### 6.2 일반 증명사진

- 3×4cm를 300dpi로 환산한 354×472px를 기본값으로 사용하며 법정 보편 규격이라고 표현하지 않는다.
- 원본 배경, 흰색, 연한 회색, 연한 파란색을 지원한다.
- 배경 분리는 브라우저에서만 수행하고 품질이 나쁘거나 실패하면 원본 배경으로 즉시 돌아갈 수 있어야 한다.
- 복잡한 마스크 브러시 대신 자동 후보와 수동 위치·확대 조정을 제공한다.

### 6.3 주민등록증 사진

- 3.5×4.5cm가 공식 물리 규격이며 413×531px는 이를 300dpi로 환산한 서비스 기본값이다.
- JPEG와 PNG 출력을 제공하고 DPI 기록 상태를 결과에 표시한다.
- 기본은 원본 배경 유지다. 배경 교체가 제공되면 일반 모드로 분리하고 제출처 기준 확인 경고를 항상 표시한다.
- 모든 온라인 제출 경로의 공식 픽셀 규격이라는 표현을 금지한다.

### 6.4 YouTube 채널 배너

- 결과는 2560×1440px, 16:9, 실제 파일 크기 6MB 이하다.
- 공식 최소 캔버스 2048×1152와 최소 안전영역 1235×338을 기준 데이터로 저장하고, 2560×1440에서는 동일 비율로 환산한다.
- 전체 TV 영역, 데스크톱·모바일 예상 영역, 텍스트·로고 안전영역을 구분해 표시한다.
- 원본 맞춤, 블러 배경 채움, 왼쪽·가운데·오른쪽 배치를 제공한다. 실제 기기 렌더링은 “예상 표시”다.
- 투명 입력은 사용자가 고른 배경 위에 합성하며 JPG/PNG 선택과 추천 기본값을 제공한다.

### 6.5 파비콘 패키지

- 래스터 PNG/JPEG/WebP를 입력으로 받는다. 안전한 SVG 정화가 구현·검증되지 않으면 SVG 입력은 거부한다.
- ZIP에는 16/32/48을 포함한 `favicon.ico`, `favicon-16x16.png`, `favicon-32x32.png`, `favicon-48x48.png`, `apple-touch-icon.png`(180), `icon-192.png`, `icon-512.png`, `site.webmanifest`, 설치 안내와 README가 포함된다.
- ICO와 ZIP을 다시 열어 각 엔트리와 이미지 크기, manifest JSON을 검증한다.
- 꽉 채우기, 안전 여백, 원형·둥근 사각형·투명·단색 배경을 제공하고 16/32/48px 미리보기를 제공한다.

### 6.6 사진 개인정보 정리

- JPEG, PNG, WebP를 우선 지원하며 HEIC은 v1에서 안정적인 로컬 처리 경로가 검증되지 않으면 명시적으로 지원하지 않는다.
- GPS, 기기·렌즈, 촬영 일시, 편집 프로그램, 작성자·설명, EXIF 미리보기, 개인정보성 XMP/IPTC를 사람이 이해할 수 있는 이름으로 표시한다.
- 다운로드 전에 제거/유지 대상, 재인코딩 여부, 품질 변화 가능성, 콘텐츠 자격 증명 영향 가능성을 표시한다.
- JPEG scan data, PNG IDAT, WebP image payload를 유지하는 무손실 메타데이터 제거를 우선한다. 약속한 보존 속성은 결과를 재파싱해 확인한다.
- C2PA/JUMBF/Content Credentials가 감지되면 제거 옵션을 주지 않고, 파일 수정으로 유효성이 손상될 수 있음을 경고한다. “보존 보장”도 하지 않는다.

## 7. 공통 UX·접근성

모바일 우선으로 한 화면에 하나의 주 행동을 둔다. 업로드는 드롭존과 명시적 파일 선택 버튼을 모두 제공한다. 편집기는 큰 미리보기, 드래그/터치 이동, 확대 슬라이더, 회전, 자동 맞춤 재실행, 초기화, 키보드 화살표 이동을 지원한다. 상태와 오류는 `aria-live`, 처리 중에는 `aria-busy`로 알리고 색상만으로 결과를 전달하지 않는다.

WCAG 2.2 AA를 목표로 하며 키보드 흐름, 포커스 표시, 터치 타깃, 대비, reduced motion, 안전영역·크롭의 텍스트 대안을 검증한다.

## 8. 파일·오류 정책

확장자와 MIME만 신뢰하지 않고 파일 signature도 확인한다. 빈 파일, 손상 파일, MIME 불일치, 용량·픽셀 한도 초과, 지원하지 않는 형식, 디코드·Canvas·Worker·압축·ZIP·다운로드 실패를 각각 해결 방법과 함께 표시한다. 새 작업이 이전 비동기 결과를 덮어쓰지 않도록 작업 토큰 또는 취소 신호를 사용한다.

출력 파일명은 사용자 입력과 분리한 예측 가능한 ASCII 이름을 사용한다. 예: `passport-photo-413x531.jpg`, `youtube-banner-2560x1440.jpg`, `favicon-package.zip`.

## 9. 완료 조건

출시 완료 판정은 [테스트 계획](./TEST_PLAN.md)과 [출시 체크리스트](./RELEASE_CHECKLIST.md)를 따른다. 모든 필수 검사에는 실행 증거가 있어야 하며 실행하지 못한 항목은 `NOT_TESTED`, 실패는 `FAIL`로 기록한다. 공식 출처와 구현 해석은 [프리셋 출처 기록](./PRESET_SOURCES.md)을 단일 기준으로 사용한다.
